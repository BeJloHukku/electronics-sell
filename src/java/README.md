# Объектно-ориентированная реализация обработки заявок

Консольная программа проверяет данные заявки и остатки, рассчитывает сумму по действующим ценам и резервирует весь состав заказа. Формат JSON соответствует процедурной версии КТ2. В комплект включён тот же демонстрационный набор данных.

## Сборка и запуск

- **Для запуска Gradle Wrapper** используйте JDK 11 (`JAVA_HOME` должен указывать на установленный JDK). Сборка проверена с Gradle 8.14.3.
- **Целевая версия приложения** – Java 11 (`options.release = 11` в `build.gradle`). Для запуска собранного приложения нужна Java 11 или более новая версия.

При первом запуске Gradle Wrapper скачивает Gradle 8.14.3 и зависимости проекта. Выполните команды из каталога `src/java`.

```sh
java -version
./gradlew build installDist
cp data.json data-demo.json
./build/install/electronics-orders/bin/electronics-orders --data data-demo.json --list
./build/install/electronics-orders/bin/electronics-orders --data data-demo.json --show 101
./build/install/electronics-orders/bin/electronics-orders --data data-demo.json --request-id 104 --at 2026-11-01T12:00:00+03:00
```

- `--list` (режим по умолчанию) выводит номера и статусы заявок.
- `--show НОМЕР` показывает сохранённый результат.
- `--request-id НОМЕР` обрабатывает заявку и сохраняет результат в указанном файле.
- `--at` задаёт момент расчёта в ISO 8601 с часовым поясом. Если параметр опущен, используется текущее время.
- Если путь `--data` опущен, используется `data.json` из текущего каталога. Для сравнения Java и Python запускайте программы на отдельных копиях входного файла.

В Windows используйте `gradlew.bat build installDist` и `build\install\electronics-orders\bin\electronics-orders.bat`.

## Автоматические тесты

Из каталога `src/java` выполните `./gradlew test` (в Windows – `gradlew.bat test`). Тесты обрабатывают временные копии демонстрационного JSON и проверяют повторную обработку подтверждённой заявки, недостаток суммарного остатка и отсутствие единственной действующей цены.

## Контрольный пример

В исходном `data.json` заявка 101 подтверждена и содержит две товарные позиции. Команда `--show 101` выводит:

```text
Заявка: 101
Статус: Подтвержден
Заказ: 1
Сумма: 64 970,00 руб.
Весь состав заказа зарезервирован.
```

Повторная обработка заявки 101 возвращает тот же результат, сохраняя исходные остатки. Для заявки 104 команда обработки из примера выводит:

```text
Заявка: 104
Статус: Ожидает уточнения цены
Заказ: 3
Резервирование не выполнено: для одной или нескольких позиций нет единственной действующей цены.
```

## Структура

| Операция КТ2 | Реализация на Java |
| --- | --- |
| `check_request` | `RequestDataCheck.check` собирает все замечания к обязательным полям и позициям заявки. |
| `check_stock` | `StockAvailabilityCheck.check` суммирует спрос по товару и создаёт результат для каждой позиции. |
| `calculate_total` | `Order.calculateTotal` подбирает единственную цену на момент расчёта и фиксирует цены только после проверки всех позиций. |
| `reserve_order` | `OrderProcessingService.reserveOrder` повторно проверяет наличие всего состава и только после этого списывает остатки. |

`RequestDataCheck` и `StockAvailabilityCheck` реализуют интерфейс `CheckRule`. Классы `Email` и `PhoneNumber` наследуют общий метод проверки заполненности от `Contact` и переопределяют нормализацию контакта. `JsonStorage` проверяет данные при загрузке и перед записью. Обновление выполняется под блокировкой для процессов Java через временный файл и атомарную замену.

Количество и остатки представлены типом `int`, идентификаторы и суммы в копейках – типом `long`. При переполнении расчёта программа сообщает об ошибке и сохраняет исходный JSON.
